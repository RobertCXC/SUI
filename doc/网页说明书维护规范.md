# 网页说明书维护规范

## 目标与范围

为 SUI 使用者提供可离线浏览、可在线访问的中文 HTML 说明书，覆盖接入、控件 API、原生样式、主题令牌、转换器和排查。生成结果保存在仓库 `docs/` 中，可直接打开、由普通静态服务器托管，也由 GitHub Pages 发布。

文档网站展示说明与代码；真实 WPF 控件效果和操作状态由 `samples/SUI.Gallery` 展示。网页主题切换只改变文档页面，不代表库支持运行时主题切换。

## 内容规则

1. `doc/使用手册.md` 是正文唯一内容源；先核对当前源码，再更新说明。不要手工维护两份 API 文档。
2. 属性名、类型、默认值、命名空间和资源键必须与实现一致。接入片段写明上下文；示例中的业务模型、绑定和页面由宿主实现。
3. 明确区分可用控件与骨架。不能把路线图、静态示意或计划能力写成已实现功能。
4. 新增章节时更新手册目录。标题保持稳定，避免无必要地破坏链接；目录和网页搜索从实际标题及正文生成。
5. 文档风格沿用现有手册：中文解释、准确的类型与资源名、可复制代码、必要的限制说明。
6. 许可说明引用仓库 `LICENSE`，完整条款以该文件为准。

## 文件分工

| 文件 | 职责 |
| --- | --- |
| `doc/使用手册.md` | 接入说明、API、代码示例与排查正文 |
| `scripts/Build-Docs.ps1` | PowerShell 7 构建与一致性检查，无额外模块依赖 |
| `scripts/docs/template.html` | 页面框架、介绍与导航容器 |
| `docs/assets/` | 本地 CSS、JavaScript 和站点图标 |
| `docs/index.html` | 提交到版本库的 HTML 生成结果，支持双击打开 |
| `.github/workflows/docs.yml` | 检查生成结果；Pull Request 只检查，默认分支推送通过后部署到 GitHub Pages |

## 开发流程

在仓库根目录运行（已安装 PowerShell 7）：

```powershell
pwsh -File scripts/Build-Docs.ps1
pwsh -File scripts/Build-Docs.ps1 -Check
Start-Process ./docs/index.html
```

构建脚本以自身位置确定仓库路径，也可以从其他工作目录运行。`-Check` 不写文件：正文、模板变化后未重新生成 HTML，或者本地资源、章节链接无效时，以非零状态退出。

文档 Pull Request 会运行一致性与脚本检查，但不会更新线上站点。文档变更合并到默认分支且检查通过后，工作流会发布整个 `docs/` 目录；也可以在默认分支手动运行工作流重新发布。首次启用时，在 GitHub 仓库 **Settings → Pages → Build and deployment** 中将 **Source** 设为 **GitHub Actions**。

需要 HTTP 预览时，可在安装 Python 的环境中运行：

```powershell
python -m http.server 4173 --bind 127.0.0.1 --directory docs
```

浏览器访问 `http://127.0.0.1:4173`。托管时发布整个 `docs/` 目录并保持资源相对路径。线上站点位于 `https://robertcxc.github.io/SUI/`；源码链接指向项目 GitHub 仓库，离线时仍可阅读全部正文和示例，但打开源码链接需要网络。

## 验收规则

- 正文、模板、HTML 一致；本地资源和站内锚点无缺失。
- 无 CDN、远程字体或运行时 Markdown 请求；断网和 `file://` 模式下仍能阅读、导航和搜索。
- 验证中文名称、英文 API、代码内容搜索、无匹配反馈、Enter 跳转与 Escape 关闭。
- 验证代码复制反馈；剪贴板不可用时提供手动选择复制，不错误提示成功。
- 验证桌面、窄屏目录、章节跳转、键盘焦点、明暗文档主题及打印布局。
- JavaScript 不可用时，正文和章节目录仍然可读。
- 运行 `dotnet build SUI.slnx`，确认文档改动不影响 WPF 构建。
- 只修改说明书时不要求改 Gallery 页面；若同时改库的外观或交互，按根目录 `AGENTS.md` 同步并运行 Gallery。
